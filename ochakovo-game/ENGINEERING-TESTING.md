# Проверка инженерного участка «Бутылка есть. А сигнал?»

Проверено 23 октября 2026 года. Открыть: `http://127.0.0.1:4174/#mission/engineering`.

## Реализация

- `dist/shift-engineering.js`: семь этапов, отдельная модель случая, ответы оператора, расхождения в проходах 2 и 5, семь диагностических источников, пять гипотез, обоснование работы, действия специалиста, испытание и запись.
- `dist/engineering.css`: локальные стили, схема конвейера, состояния датчика, панели и механизма, адаптация под телефон, фокус и отключение движения.
- `dist/index.html`: подключение инженерных ресурсов с отдельной версией кеша.
- Описание инженерной роли и итог паспорта обновляются только для `engineering` при регистрации модуля. Общий движок для этого не переписывался.
- README и таблица требований: обновлены только строки об инженерном эпизоде.

## Проверки логики

Команда из корня рабочей папки: `node work/engineering-case.test.cjs`.

Результат: PASS, 16 проверок переходов между этапами и дополнительные проверки ветвей:

- Нельзя перескочить к незавершённому этапу.
- Без уточнения симптомов и статуса участка сообщение не принимается. Неподтверждённая замена датчика отделяется от наблюдения.
- Проверка механизма раньше сопоставления счёта объясняется, а не принимается за диагноз.
- Неверные проходы и гипотеза о потере передачи оставляют игрока на этапе; выход и вход сравниваются явно.
- Нужны документация, история и осмотр. Несвязанный источник не подтверждает гипотезу; минимум две версии сопоставляются с данными.
- Выбор обслуживания без двух прямых оснований не начинает работу.
- Подготовку безопасных условий, обслуживание и подготовку испытания выполняет специалист; стажёр наблюдает.
- Три успешных бутылки не дают основания возвращать участок к обычной работе.
- Проверены два прохода по шесть и пустой промежуток. Для принятия результата нужны четыре наблюдения и соответствующее заключение.
- Ошибки записи не стирают остальные строки.
- Завершение доступно после передачи результата и согласования; интерфейсное действие стажёра не является самостоятельным пуском.
- После закрытия случая предыдущие этапы можно просмотреть без изменения переданной записи.
- После выхода обработчики модуля перестают рисовать интерфейс.

## Реальный браузер

Внутри приложения пройден весь эпизод, включая неправильный выбор зоны, версию о передаче, ранний возврат к работе и пустую запись. После корректной передачи и согласования открытие записано в паспорт. Перезагрузка страницы завершения сохранила результат.

Кнопки вопросов и выбора проверены клавишей Enter; при переходе фокус попал на заголовок нового этапа. Отдельные кнопки предусмотрены для каждого действия, требуемого для прохождения. Новые ошибки и предупреждения JavaScript в проверенной вкладке не обнаружены.

Визуальный инспектор выполнил рендер на ширинах 1440, 768 и 390 пикселей. Финальный отчёт — `../work/engineering-qa-final/report.json`; снимки — в той же папке. На всех трёх ширинах:

- горизонтальное переполнение — 0;
- ошибок консоли — 0;
- найденных проблем контраста — 0;
- блокирующих замечаний инспектора — 0.

Осталось предупреждение инспектора о существующем тёплом фоне всей игры `#faf9f6`. Он сохранён как часть текущего оформления. Механический детектор Impeccable выдал рекомендации о размерах шрифта вне неполной шкалы DESIGN.md; проверка рендера подтверждает читаемость новых элементов. Общее оформление и DESIGN.md не менялись.

CSS поддерживает `prefers-reduced-motion`, ручную паузу и неактивную вкладку. Игровые состояния меняются синхронно, завершения анимации ждать не нужно.

## Общая рабочая папка

Во время работы другие процессы обновляли историю, лабораторию, розлив, склад и общий движок. Эти изменения не откатывались и не редактировались в рамках инженерного эпизода. Контрольные суммы этих файлов поэтому не используются как утверждение об их неизменности; проверялась совместимость инженерного модуля с актуальной общей страницей.

## Границы проверки

Результат относится к локальному стенду и проверенным состояниям. Это учебный сюжет, не описание оборудования, регламента обслуживания или процедуры допуска «Очаково». Диагностические числа, обозначение S1 и состав испытания условные. Отдельная случайная повторная неисправность не добавлялась.
