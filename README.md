# СМЕНА · Очаково

Работающий локальный фрагмент мобильной браузерной игры. **Этап A, сцены 3.1–3.5.** После инженера и технолога появляется «Демонстрационный фрагмент завершён». Остальная первая смена и дни 2–3 не реализованы.

## Запуск

Требуются Node.js 24+ и pnpm. Проверено с Node 24.19.0 и pnpm 11.25.0. Зависимости закреплены в `package.json` и `pnpm-lock.yaml`.

```powershell
pnpm install --frozen-lockfile
pnpm dev
```

Открыть http://localhost:5173 . Для телефона в той же сети можно использовать сетевой адрес, который печатает Vite. Регистрация и ключи API не нужны.

```powershell
pnpm build
pnpm preview
```

Готовая сборка находится в `dist/`. Production preview: http://localhost:4173 . Это локальный статический сервер для просмотра, публикация не выполнялась.

## Как играть

Нажать «Приступить», открыть памятку и журнал, прочитать газету. Затем открывать предметы на столе. Нажать поле пропуска или заявки, потом соответствующее поле другого документа или журнала. Выбранные значения видны над столом. Сравнение бесплатно.

«Проверить» расходует один запрос и приносит ответ отдела. Повторный запрос к тому же посетителю бесплатно перечитывает ответ. Только «Пропустить» или «Отказать» завершает случай. Лист сверки заполняет сам игрок. Текст не прокручивается. Справочные документы показаны целиком, если помещаются; только при недостатке места появляются «Назад» и «Дальше». На телефоне вкладки равномерно заполняют два ряда. На широком планшете окно проходной слева, стол справа.

Сохранение автоматическое, локальное. Кнопка со стрелкой в шапке («Начать заново») запрашивает подтверждение сброса; «Переиграть фрагмент» в конце сразу начинает новое прохождение. Включение звука — кнопка динамика. «Об игре» содержит оговорку о вымысле и источники.

## Проверки

```powershell
pnpm test
pnpm exec playwright install chromium webkit
pnpm test:browser
```

Автоматические проверки браузера ожидают работающий сервер на 5173. Для проверки сборки:

```powershell
$env:QA_URL = 'http://127.0.0.1:4173/'
pnpm test:browser
```

Если системная папка браузеров недоступна для записи, можно установить их в проект:

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH = "$PWD/.browsers"
pnpm exec playwright install chromium webkit
```

Скрипты QA автоматически используют `.browsers`, если эта папка есть. Скриншоты и JSON-отчёт: `output/playwright/`. Результаты и ограничения — в [docs/testing.md](docs/testing.md). Матрица требований — [docs/qa-inventory.md](docs/qa-inventory.md).

Короткая проверка трёх композиций при работающем preview: `node scripts/layout-smoke.mjs`. Полный прогон браузеров для каждой косметической правки не требуется.

При работающем preview на 4173 замер производительности запускается командой `pnpm test:performance`. Профиль сети и ограничения измерения зафиксированы в отчёте.

## Структура

- `src/scenario.ts` — типизированные данные двух посетителей, реплики и интересы.
- `src/model.ts` — чистые переходы состояния, сравнение, оценка решений, сохранение.
- `src/main.ts` — рабочее место и взаимодействия; один делегированный обработчик на приложение.
- `src/style.css`, `src/revision.css` — предметная сцена, адаптивные композиции и анимации.
- `src/audio.ts` — короткие синтезированные звуки после жеста пользователя.
- `public/assets/` — официальный знак и оригинальные оптимизированные WebP.
- `tests/rules.test.ts` — содержательные проверки правил, запросов, интересов и хранилища.
- `scripts/browser-qa.mjs` — прохождение в Chromium и WebKit, размеры и доступность управления.
