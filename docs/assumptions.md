# Допущения и границы этапа A

1. Реализованы только 3.1–3.5: первый день на проходной, Виктор Сергеевич, инструктаж, газета № 1, Андрей Волков, Елена Миронова, остановка демо. Ни логиста, ни курьера, ни протокола полной смены, ни расчёта рекомендаций, ни дней 2–3 в коде нет.
2. **Ответ технологического отдела отсутствует в PDF.** По заданию он подтверждает техническую ошибку T-218, выдаёт исправленную заявку T-281 и отзывает прежнюю. До этого номера остаются несогласованными. Само сравнение ничего не исправляет. Запрос не принимает решение о проходе.
3. Учебная процедура при неразрешённом противоречии: если запросы есть, требуется уточнение. Отказ до уточнения получает замечание. Если запросов нет, корректно отказать в текущем проходе и направить на переоформление. Это объясняется в памятке до первого посетителя. Внешность не является критерием.
4. Каждый посетитель может получить один содержательный ответ отдела. Повторное чтение бесплатно. Максимально в коротком фрагменте можно потратить два запроса из трёх. Нулевой остаток проверяется тестовым состоянием, подготовленным до загрузки приложения.
5. Для оформления добавлены вымышленные ID технолога 0256, инженерная заявка И-142, служебные подписи, утренние часы и макеты документов. Эти реквизиты не выданы за источниковые данные PDF или реальные документы компании. ID 0142, действительность допуска, линия № 2 и плановый осмотр инженера сохранены по сценарию и изображению страницы 5.
6. Инженер и технолог знакомят с профессиями после любого решения, включая ошибочное. В случае отказа нет нелогичной благодарности за проход: используется отдельная реплика. Проверка документов и интересы хранятся в разных полях. Автоматический карьерный рейтинг не рассчитывается.
7. Продолжительность «около 3–5 минут» — ориентир интерфейса для чтения и исследования двух случаев, не результат пользовательского исследования. Полная первая смена в демо не обещается.
8. Выбранное поле сохраняется при смене документов. При выдаче исправленной заявки старое выделение и старое сравнение очищаются: устаревший T-218 нельзя оставить как актуальное выбранное поле. После перезагрузки выделение сбрасывается, содержательный прогресс сохраняется.
9. Стек: TypeScript + Vite + семантический HTML/CSS. Phaser не нужен для двух неподвижных ракурсов и предметной сцены: спрайты, передача листа, штамп, уход посетителя и шлагбаум анимируются средствами CSS; текст остаётся настоящим текстом. Нет непрерывного игрового цикла, canvas-буфера или зависимости от DPR. Готовые WebP ограничены разрешением.
10. После доработки по замечанию заказчика текст не прокручивается. Справочные документы показываются целиком, если помещаются; при недостатке места появляются листы с кнопками перелистывания. Вместимость измеряется при открытии и изменении размера. Все правила доступны до первого решения. На телефоне вкладки заполняют два равномерных ряда; при семи вкладках это четыре и три. Выбранная пара сохраняется при смене документа. В альбоме и на широком планшете окно слева, стол справа; портрет масштабируется по высоте окна.
11. Звук изначально выключен. После нажатия на переключатель короткие сигналы синтезируются Web Audio. При уходе в фон контекст приостанавливается; постоянной музыки и рендера нет. `prefers-reduced-motion` отключает движения.
12. Прогресс хранится под `ochakovo-smena-a-v1` только в localStorage данного браузера. Хранилище может быть заблокировано — игра продолжает работать с уведомлением. Серверной части, отправки данных, аналитики, регистрации, запросов к модели во время игры нет.

Дальнейшие этапы и публикация требуют отдельного одобрения заказчика.
